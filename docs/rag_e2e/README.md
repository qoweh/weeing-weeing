관련도 필터, 구조 기반 청킹을 평가한 기록이다. 검색 평가와 챗봇의 최종 응답
평가를 구분하고, 같은 실험의 결과는 아래 보고서 한곳에서 관리한다.

## 평가 조건과 지표

- **모델 구분:** 2026-10-27~30 검색 실측은 `BAAI/bge-m3`와
  `BAAI/bge-reranker-v2-m3`를 사용했다. 11-03 o02 응답도 기존 평가 worktree의
  검색 구성을 사용했다. 현재 코드의 기본은 해시 임베딩·리랭커 끔이며 Voyage를
  선택할 수 있다. 과거 BGE 수치를 현재 Voyage 성능으로 인용하지 않는다.
  구성 변경은 [EMBEDDING_API](../EMBEDDING_API.md)를 참고한다.
- **표본 구분:** 12·18·36·24·20질문은 서로 다른 평가다. 분모와 모델이 다른
  결과를 하나의 개선 추이로 합산하지 않는다. 새 질문도 같은 PDF 3종을 사용했다.
- **Hit@K:** 정상 질문 중 기대 문서·본문 키워드를 만족하는 첫 근거가 상위 K개에
  있는 질문 비율이다. 전체 정답 청크 집합에 대한 Recall@K와 구분한다.
- **MRR:** 정상 질문의 첫 정답 순위 역수 평균이다. 상위 5개에 없으면 0으로 집계한다.
- **근거 없음 거절:** 요청 정보가 없는 질문에서 검색 결과가 빈 경우다.
  검색 후보가 남은 사실과 챗봇이 근거 없는 답변을 생성한 사실은 별도로 판정한다.
- **관련도 하한:** 리랭커 점수에 적용하는 필터다. RRF 점수·확률·답변 신뢰도와
  다르며, `0.02`를 모델 간 공통 기준으로 사용하지 않는다.

## 보완할 사항

| 보완 항목 | 추가로 남길 근거 |
|---|---|
| 현재 공급자 구성의 재평가 | 동일 문서·질문·후보 수로 Voyage 리랭킹 전후와 하한을 다시 측정. 과거 BGE 수치와 조건을 분리 |
| 정답표 정교화 | 본문 기준 정답 청크와 관련도 등급을 검토하고 Recall@K·nDCG를 계산. 제목·문맥만 일치하는 결과는 별도 확인 |
| 검색 순위 점검 | 청킹 비교 q12·q13과 독립 질문 u03·u11·u12의 후보·정답 청크를 대조 |
| 근거 부족 응답 범위 확대 | n01·n02·n03·n06·n09의 실제 답변·검색 근거를 함께 검토하고, o02도 반복 실행으로 일관성 확인 |
| 통합·운영 조건 검증 | 승인 보고서 혼합 검색, 개정·삭제 전후 출처 유효성, API·대화 저장·화면 경로를 구분해 검증. 속도는 캐시·부하를 고정해 별도 측정 |

실제 인증 확인·유료 API 실행은 사용자가 자기 터미널에서 수행한다.
자동 검증에는 가짜 SDK·클라이언트만 사용한다.

## 기록 관리

이 정리는 기존 측정 결과의 통합이며 새로운 성능 측정이 아니다.
초기 중단 과정과 이후 보완된 준비 오류의 서술을 덜어내고, 완료된 측정·조건·검토
결과를 주제별로 모았다. 측정된 낮은 순위와 빈 결과 여부도 비교표에 유지한다.
보완 과제는 위 표에서만 관리한다.

새 실행의 원본은 `outputs/rag_e2e/<실행명>/` 또는
`outputs/llm_evaluation/<실행명>/`에 두고, 공유할 때 이 폴더의 해당 주제 보고서에
조건·표본·결과·산출물 위치를 추가한다. 로컬 `outputs/`는 Git 제외 경로이므로
공유 문서의 핵심 결과와 판단 조건은 이 보고서들만으로 읽을 수 있게 남긴다.
