# 정비이력 시연 데이터 등록

`seed_330_reports.py`는 매뉴얼을 참고한 22개 코드별 15건, 총 330건의 사례를 만든다. 각 코드에는 원인·조치 5개 유형과 유형별 유사 기록 3건이 있다. 복구 확인 수치도 시연용으로 생성된 값이다. 실제 센서 감지·정비·사람의 결재나 LLM 실행 기록은 아니며, 분석의 모델 필드는 `sample/manual`이다. 시연 환경에서만 사용한다.

기존 22건 일괄 등록의 사건 ID를 첫 사례로 사용한다. 이미 동일 사건에 승인 보고서가 한 건 있으면 새 보고서를 만들지 않고, 이후 사례의 사건 ID도 고정해 중복 생성을 방지한다. 승인 시 생성되는 검색 등록 작업을 통해 이번 사례만 색인하며, 실패한 색인은 같은 명령으로 재시도한다.

등록 중 사건만 저장되고 보고서 승인이 완료되지 않으면 다음 실행에서 해당 사건을 알리고 중단한다. 임의로 덮어쓰거나 삭제하지 않으므로 상태를 확인해 처리한 뒤 재실행한다. 색인 중단 시 DB 보고서는 남는다.

## AWS 실행

API 이미지에 이 스크립트가 배포된 후 EC2의 compose 디렉터리에서 실행한다. PostgreSQL·Qdrant와 임베딩 설정, 활성 시연 계정(현장 점검자·보전 팀장·관제 담당자)이 필요하다. 실제 환경 변수나 키를 출력하지 않는다.

```bash
docker compose exec -T api python scripts/seed_330_reports.py \
  --aws --author I4001 --reviewer L2001 --approver C1001
```

`--aws`는 Docker 내부 DB 호스트 `postgres`와 Qdrant 호스트 `qdrant`에서만 허용한다. 로컬 실행은 이 옵션을 빼고 로컬 PostgreSQL과 Qdrant 서버를 사용한다. 외부 임베딩 공급자를 사용하면 색인 과정에서 API 비용이 발생할 수 있다. 종료 후 출력된 신규·기존·검색 등록 건수, 사이트의 정비이력, Qdrant 검색 결과를 확인한다.
