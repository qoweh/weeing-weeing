# 로그인과 권한 (#62)

코드: `api/auth.py`(API·권한 의존성), `db/users.py`(계정·세션 저장), `contracts/user.py`(`UserAccount`).

## 한눈에

- **로그인**: `POST /auth/login {employee_no, password}` → `access_token`. 이후 요청에 `Authorization: Bearer <토큰>`
- **세션**: DB `user_session` 행 하나. 유효 시간은 `AUTH_SESSION_HOURS`(기본 12시간, 교대 근무 한 번). 로그아웃·비활성화·비밀번호 변경은 행을 지워 **즉시** 끊는다
- **권한 두 갈래**: 직책(`role`, 4종) = 업무 권한, `is_admin` = 계정 관리 권한. 관리자라도 직책이 다르면 직책 권한은 없다
- **시연 계정**: `make seed-users`(DB 필요). 관리자 `ADMIN` + 직책별 1명. 비밀번호는 만들 때 한 번 출력되거나 `ARGS=--ask-password`로 입력
- **`ADMIN` 계정의 직책**: 직책은 필수라 `ADMIN`(표시 이름 "시스템 관리자")은 **관제 담당자 + 관리자**다. 그래서 계정 관리뿐 아니라 관제 업무 권한(사건 접수, 보고서 최종 승인 등)도 가진다. 노션 직책은 4종이고 "시스템 관리자"라는 별도 직책은 없다(10/16 회의). 업무 권한 없는 관리자 계정이 필요해지면 `role`을 비울 수 있게 계약을 바꾼다

## API

| 메서드·경로 | 누가 | 하는 일 |
|---|---|---|
| `POST /auth/login` | 누구나 | 토큰 발급. 틀리면 401(사번 없음·비밀번호 틀림·막힌 계정을 구분하지 않음) |
| `POST /auth/logout` | 로그인 | 이 토큰 폐기 |
| `GET /auth/me` | 로그인 | 내 계정 |
| `POST /auth/password` | 로그인 | 내 비밀번호 변경(현재 비밀번호 확인). 내 세션 모두 끊김 |
| `GET /users` | 관리자 | 계정 목록 |
| `POST /users` | 관리자 | 계정 생성. 사번 중복 409, 비밀번호 8자 미만 422 |
| `PATCH /users/{사번}` | 관리자 | 이름·직책·관리자·활성 중 보낸 칸만 변경. 마지막 관리자를 없애면 409 |
| `PUT /users/{사번}/password` | 관리자 | 비밀번호 재설정. 그 사람 세션 모두 끊김 |
| `GET /llm-usage?days=1~30` | 관리자 | Langfuse LLM 사용량 요약(토큰·비용·호출 수·모델별·일별). Langfuse 실패는 200 + `status`(`not_configured`·`failed`). 마이페이지 "LLM 사용량" 카드(#207) |

`make api` 후 http://localhost:8000/docs 의 **Authorize** 버튼에 토큰을 넣으면 문서 화면에서 바로 시험할 수 있다. DB가 꺼져 있으면 503.

## 문서 공통 열람

로그인한 사용자는 직책·작성자·관리자 여부와 관계없이 매뉴얼·SOP·정비 보고서를
조회할 수 있다. 보고서는 초안·반려 판과 과거 버전도 포함한다.
`GET /reports?scope=all`은 모든 보고서 목록, `GET /reports/{id}`와 버전 조회는
모든 로그인 사용자에게 허용한다. 기존 `scope=mine`은 내 보고서 필터이고
`scope=review`는 직책별 내 결재 대기 목록이다.

공통 열람은 작성·수정·제출·결재 권한을 부여하지 않는다. 보고서 변경은 기존 작성자·
직책 조건을, 대화는 본인 소유권을 계속 검사한다. 비활성 계정·만료 세션도 허용하지 않는다.
챗봇의 정비 근거 검색은 별도 정책으로 최신 승인 보고서의 사람 작성 칸만 사용한다.
초안·반려 보고서를 원문으로 읽을 수 있어도 AI의 정비 근거로 자동 색인하지 않는다.

## 다른 API에 권한 걸기

```python
from fastapi import Depends

from weeing_weeing.api.auth import CurrentUser, require_admin, require_roles
from weeing_weeing.contracts import Role


# 로그인만 필요
@router.get("/incidents")
def list_incidents(user: CurrentUser): ...


# 직책 제한(여러 개 가능). 통과한 사용자를 받으려면 Annotated로 받는다
@router.post(
    "/reports/{report_id}/review",
    dependencies=[Depends(require_roles(Role.MAINT_LEAD))],
)
def review(report_id: str): ...
```

결재 기록(`ApprovalStep.user`)·조치 기록(`ActionTaken.by`)에는 `user.employee_no`를 넣는다. 요청 본문으로 받은 사번을 믿지 않는다.

**매뉴얼 관리**: 문서 목록(`GET /documents`)과 업로드 상태 조회는 로그인한 사용자가 할 수 있다. 등록(`POST /documents`)과 삭제(`DELETE /documents/{doc_id}`)는 관제 담당자(`Role.CONTROL`)만 할 수 있다. `is_admin=True`여도 다른 직책이면 등록·삭제할 수 없다. 화면에서는 관제 담당자에게만 문서 등록 메뉴를 표시하고, 다른 직책이 등록 화면에 접근하면 폼 대신 권한 안내와 문서 목록 이동 버튼을 제공한다.

센서 WebSocket은 사람의 로그인과 별개인 송신 전용 Bearer 인증을 사용한다.
운영 필수화·로컬 호환 설정과 읽기 전용 로그인 조회는 [AWS_TELEMETRY](AWS_TELEMETRY.md)를 따른다.

## 직책별 권한표 (제안, 미확정)

노션 "8. 사용자·권한"의 직책 4종과 ReportStatus 흐름을 따른다. #62는 보고서 작성·제출(현장 점검자), 검토 승인(보전 팀장), 최종 승인(관제 담당자)을 API·저장소에서 검사하며 본인 결재를 금지한다([REPORTS](REPORTS.md)). 다른 업무 권한은 여전히 제안이며 아래 미결 항목은 강제하지 않는다.

| 기능 | 관제 담당자 | 보전 팀장 | 현장 책임자 | 현장 점검자 |
|---|---|---|---|---|
| 모니터링·알람·사건 조회 | ✓ | ✓ | ✓ | ✓ |
| 사건 접수(`ACKNOWLEDGED`) | ✓ | | | |
| 보고서 작성·제출(정비 결과 칸) | | | | ✓ |
| 보고서 검토 승인(`REVIEWED`) | | ✓ | | |
| 최종 승인(`APPROVED`, 확정) | ✓ | | | |
| 격리·리셋 확인 서명 | | | ✓ | |
| 재가동 승인 | ? | | ? | |

`?`는 노션에서도 정하지 않은 항목이다(CONTRACTS.md "아직 정하지 않은 것").

## 고려한 선택지

| 결정 | 선택지 | 고른 것과 이유 |
|---|---|---|
| 로그인 방식 | **DB 세션 토큰** / JWT / HTTP Basic | DB 세션. 로그아웃·계정 정지가 즉시 반영되고 새 의존성이 없다. 요청마다 DB 조회 1번이지만 사용자가 수십 명이라 문제없다. JWT는 서명 키 관리가 필요하고 강제 만료에 블랙리스트가 필요하다. Basic은 HMI가 비밀번호를 계속 들고 있어야 한다 |
| 계정 관리 권한 | **별도 `is_admin`** / 관제 담당자에게 | 별도 표시. 업무 권한(직책)과 시스템 권한을 섞지 않는다. 실제 MES·HMI도 시스템 관리자를 따로 둔다 |
| 적용 범위 | **새 API만** / 문서 업로드에도 | 새 API만. 기존 송신기·테스트를 깨지 않고 HMI 붙일 때 건다 |
| 비밀번호 해시 | Argon2id(argon2-cffi) / bcrypt / **scrypt(표준 라이브러리)** | scrypt. OWASP가 Argon2id 다음으로 권장하는 방식이고 의존성이 늘지 않는다. 해시에 매개변수를 함께 저장해 나중에 바꿔도 옛 해시를 검증한다 |
| 토큰 저장 | 원문 / **SHA-256** | 해시만 저장. DB가 새도 토큰을 쓸 수 없다 |
| 비밀번호 규칙 | **길이 8자 이상 + 공백뿐·사번과 같은 값 금지** / 문자 종류 조합 강제 | 앞쪽. NIST SP 800-63B도 조합 강제보다 길이와 뻔한 값 차단을 권한다 |
| 마지막 관리자 | 검사 없음 / **활성 관리자가 0명이 되는 변경 거부(409)** | 관리자 행을 잠근 뒤 검사해 두 관리자가 동시에 서로를 해제해도 0명이 되지 않는다 |

## 남은 일

- 로그인 실패 횟수 제한(무차별 대입 방지). 지금은 scrypt 비용(약 0.1초/회)으로 늦추고, 해시를 동시에 4개까지만 돌려 요청이 몰려도 메모리(1개 128MB)가 커지지 않게만 막았다
- 만료된 세션 행은 그 사람이 다음에 로그인할 때 지운다. 오래 안 쓰는 계정의 행은 남는다(접근은 불가, 표 크기만 늘어남)
- 보고서 외 권한표 확정과 각 API 적용. 보고서·결재와 hmi/web의 로그인 연결은 #62에서 적용했다.
