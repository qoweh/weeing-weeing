# 1단계: 이슈 계획 프롬프트

큰 이슈를 작은 하위 이슈로 나누고, 선택지마다 결정을 받는다. 코드는 아직 쓰지 않는다.
`<...>`만 바꿔서 에이전트에 붙여 넣는다. 다음 단계: [2-implement-issue.md](2-implement-issue.md)

```
이슈 #<번호>를 개발하려고 해. 내 담당은 <내 역할>이야. 지금은 계획까지만 하고 코드는 쓰지 마.

1. 조사
- 이슈, 관련 이슈, README.md, docs/, 관련 모듈 코드를 읽고 이 작업이 전체 흐름에서 어디에 있는지 정리해 줘.
- 다른 파트와 맞물리는 부분은 확인한 사실과 추측을 구분해서 알려 줘.
- 라이브러리 동작은 가능하면 작은 실험으로 직접 확인해 줘.
- (선택) 참고 자료: <노션 페이지, 문서 링크 등>

2. 결정
- 선택지가 여러 개인 결정은 임의로 고르지 마.
- 선택지마다 추천 여부, 장단점, 우리 프로젝트에 맞는지를 알려 주고 내 답을 받은 뒤 진행해.

3. 이슈 만들기 (내 답을 받은 뒤)
- PR 하나 크기로 하위 이슈를 나눠 줘.
- 각 이슈에는 배경, 결정 사항, 구현 방법, 주의할 점, 할 일, 완료 조건을 적어 줘.
  다음에 이 이슈만 보고 구현할 수 있을 만큼 자세히 써 줘.
- 상위 이슈 연결, 담당자, 라벨, 프로젝트도 연결해 줘.
```
