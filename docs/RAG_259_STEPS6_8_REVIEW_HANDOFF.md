# #259 E2E 사례 작성·교차 검토·인계 기록

작성일: 2026-11-06. 이 문서는 #259의 본인 담당인 **E2E 기대 문서·쪽, 색인 스냅샷 고정 방법, 유형별 사례 작성·검토**를 6~8번 작업에 맞춰 묶은 것이다. 사용자 지시에 따라 유형은 작성 예시로 보고 [E01~E10 사례 초안](RAG_259_E2E_CASES_V1_REVIEW.md)을 작성했으며 [Codex 자체 검토](RAG_259_E2E_SELF_REVIEW_2026-11-06.md)에서 실행 조건 4개를 수정했다. 사용자가 [정답 v1](RAG_259_E2E_GOLD_REVIEW_SHEET.md)의 10건을 전체 승인했다. GitHub #259의 최신 댓글은 연결된 계정에서 조회되지 않아 사용자가 제공한 이슈 본문을 기준으로 한다.

## 6번: 유형별 작성·검토 준비

[기대 근거 후보](RAG_259_E2E_EXPECTED_SOURCES.md)와 [원문·기존 사례 대조](RAG_259_STEP4_SOURCE_DUPLICATE_REVIEW.md)를 바탕으로 10건의 사건·센서·검색 함정·판단 초안을 작성했다. 동일 코드의 v2 사례를 사건 설명의 출발점으로 쓸 수 있으나, 검색·센서 조회를 거치는 실제 E2E fixture와 gold는 별도 확정이 필요하다.

| 유형 | 후보 ID | 이미 확인한 근거·중복 | 실제 사례가 되기 전에 고정할 입력 |
|---|---|---|---|
| 비슷한 코드 혼동 | E01 P03, E02 P04 | RULE p.8, MANUAL p.3~4; v2 `p03-*`, `p04-*`와 코드·문서 중복 | 입구/출구별 true 구간, 물체·출력·후속 수신 상태, P03/P04의 구별 근거가 실제 검색 후보에 함께 존재하는지 |
| 제한 문장 함정 | E03 P01, E08 M14 | MANUAL p.4·7과 RULE p.8·5·9; v2 `p01-*`, `m14-*`와 코드 중복 | 정상 RPM·출구 이벤트 또는 DE 첨도·충격 시각·파형/계산 창; 금지할 단정과 필요한 확인을 사람 검토로 확정 |
| 부분 근거 | E06 M10 | MANUAL p.6, RULE p.5~6; v2 `m10-*`와 코드 중복 | 외함 온도 구간·측정 위치와 **제공하지 않을** 권선/내부 온도·원인 근거의 범위 |
| 수치 모순 | E04 M02 | RULE p.4~6, MANUAL p.5; v2 `m02-*`와 코드 중복 | 사건 설명의 시각, RPM 센서 구간·단위·기동 유예와 서로 비교 가능한지 |
| 과거 사례 유혹 | E05 M07 | MANUAL p.6, RULE p.5~6; v2 `m07-*`와 코드 중복 | **같은 설비·공정·코드**의 합성 승인 보고서와 다른 부하·레시피·시각, 정비 입력·승인 상태 |
| 버전 충돌 | E07 M12 | MANUAL p.7, RULE p.5·9; v2 `m12-*`와 코드 중복 | 격리된 가상 구버전, 유효 판본의 판정 시점과 검색 가능 상태; 현재 PDF 원본 변경 금지 |
| 복합·결손 | E09 P01+M02 후보 | RULE p.4·8~9, MANUAL p.4~5; 기존 검색 질문 `v2_p08`은 **P01+M02+M06** | P01 접수와 M02 후보를 분리하고 RPM `t=9초` **레코드 부재**, M06 없음, 룰 Unknown과 분석 결과 상태 구분 |
| 안전 지시 | E10 | SOP p.4~5·7, MANUAL p.4는 P01 점검의 보조 근거; 기존 안전 검색 질문 다수 | P01 정체·RPM=0, 격리·시험·재가동 승인 증빙의 부재 |

배정된 유형의 사례는 아래 항목을 한 건씩 채워 작성하거나 다른 작성자의 기록을 검토한다. **빈 칸을 임의의 정상값·승인 상태로 메우지 않는다.**

| 사례 기록 필드 | 기입 내용 |
|---|---|
| 식별·담당 | 불변 사례 ID, 유형, 합성 표시, 작성자, 작성일, 다른 검토자 |
| 입력 | 사건 ID·룰 코드·시각·설비, 센서 조회 시작/끝·단위·표본·결측, 검색 대상 문서/보고서와 승인 상태 |
| 기대 판단 | 기대 `AnalysisResult.status` 후보, 원인 단정 금지/허용 범위, 필수 확인, 사람 승인 필요 여부. **사람 확정 전에는 gold로 사용하지 않음** |
| 문서 근거 | 문서 ID·버전·PDF 쪽·해당 본문의 적용 조건, 필수/대체 허용/보조 구분, PDF 해시 |
| 재현 조건 | `snapshot_id`, 격리 DB·색인 백업 ID, 코드·설정 버전, 해당 사례·gold 해시 |
| 검토 | 검토자·일시, 원문 대조 결과, 기존 사례와의 차이, 지적·수정 이력, 최종 승인 여부 |

사용자 지시에 따라 **10건의 사건·센서·판단 초안을 작성했다.** `expected_status`와 문서·쪽 정답은 사람 검토를 거쳐 별도 정답 v1로 확정했다. 실행 가능한 DB fixture는 아직 만들지 않았다.

## 7번: 다른 사람의 정답 검토 결과

작성자와 다른 검토자가 각 사례에 대해 다음을 확인한다. 사용자가 2026-11-06에 E01~E10의 정답 v1을 전체 승인했다. 검토 후 수정 요청은 없었다.

| 검토 항목 | 검토자가 확인할 질문 | 기록 값 |
|---|---|---|
| 원문 정확성 | 인용 문서·버전·PDF 쪽·코드·수치·시간·제외 조건이 같은가? | 통과 / 수정 필요 + 근거 |
| 사건·센서 정합 | 사건 시각과 센서 구간·단위가 대응하는가? 결측이나 정상값을 만들어 넣지 않았는가? | 통과 / 수정 필요 + 근거 |
| 근거 적용 | 필수 문서·쪽과 대체 허용 근거가 실제 주장에 충분한가? 다른 코드·구버전·과거 보고서를 현재 원인 확정 근거로 쓰지 않는가? | 통과 / 수정 필요 + 근거 |
| 안전·정답 | 원인 단정·무단 재가동·교체 지시가 없는가? 기대 상태·금지 표현·필수 확인을 사람이 확정했는가? | 통과 / 수정 필요 + 근거 |
| 재현·중복 | 색인·DB 스냅샷이 식별되고 v2·기존 검색 질문과의 차별 조건이 실행 입력에 반영됐는가? | 통과 / 수정 필요 + 근거 |

지적을 받으면 이전 사례·gold 버전과 결과를 보존하고, 변경 이유·새 해시·재검토 결과를 남긴다. 50~80% 난이도는 **확정된** 사례를 현재 운영과 같은 설정에서 실행한 뒤 평가 담당자가 측정한다. 정답 오류나 판정 오류를 먼저 검토하며 통과율에 맞춰 gold를 소급 변경하지 않는다.
