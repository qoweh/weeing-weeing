# #259 사건 분석 평가셋: 어려운 사례와 E2E 정답·스냅샷 초안

- 작성 기준: 2026-11-05. 출처는 사용자가 제공한 [이슈 #259](https://github.com/qoweh/weeing-weeing/issues/259) 본문과 저장소 기록이다. GitHub 원문·댓글은 연결 오류로 별도 확인하지 못했다.
- 대상: **사건 분석 판단 v3와 멀티 분석 E2E**. 챗봇 평가셋은 #259 범위가 아니다.
- 사용자 기여 범위: E2E 기대 문서·쪽과 색인 스냅샷 고정 방법. 사용자 지시에 따라 유형을 예시로 활용한 [E01~E10 사건 초안](RAG_259_E2E_CASES_V1_REVIEW.md)을 작성했다. 다른 사람의 정답 검토는 남아 있다.
- 팀 전체 범위와 구분: 판단 v3 전체, 판정기 확장, Langfuse Dataset 연결, 전체 E2E 실행·결과 보고와 역할 배정은 본인의 필수 담당으로 단정하지 않는다.
- 상태: **검토 전 초안**. 사례·페이지·상태·스냅샷·담당·성능 수치가 확정되거나 실행된 것이 아니다.
- 안전 경계: 실제 API 호출, 비밀 파일·인증 프로필 열람, 운영 DB·색인 변경 없이 준비했다. 실제 유료 실행은 사용자가 직접 한다.

## 1. 이슈의 목표와 제안 사항

| 구분 | 현재 문제·이슈의 제안 | 확정 여부 |
|---|---|---|
| 판단 v3 | v2의 32건은 현재 판정 기준에서 너무 쉽게 통과했다. 어려운 판단 사례 **30~50건**, 아래 8유형에서 유형별 **4~6건**을 제안한다. 기존 v2는 회귀용으로 보존한다. | 건수·비율·형식·정답은 팀 결정 전 |
| 멀티 분석 E2E | v2의 8개 코드 사례를 재활용하고 함정 사례 2건을 더한 **8~10건**을 제안한다. 검색·센서 조회·검증 경로까지 확인한다. | 선택 코드·상태·실행 환경은 미확정 |
| 정답 근거 형태 | **제안 C:** 판단 v3는 매뉴얼 한 쪽 전체(A), E2E는 스냅샷으로 고정한 실제 검색 청크(B). E2E의 gold는 청크 ID가 아닌 **문서·쪽**으로 대조한다. | 이슈에 결정 기록 필요. 확정된 정책이 아님 |
| 정답 작성·검토 | 사례 문장은 LLM 초안 가능. 기대 상태·근거·금지 표현·필수 확인은 **사람이 확정**한다. 작성자 1명과 다른 검토자 1명을 제안하며 문서 담당자가 도메인 판단을 검토한다. | 담당자·검토자 배정 전 |
| 판정기 | 제안 B: 상태·근거 ID에 금지 표현 및 필수 확인 항목의 규칙 기반 검사 추가. LLM 채점은 #209 결정 후 검토. | 판정 범위 미확정. 표현 바꾸기·오탐은 사람 검토 필요 |
| Langfuse | 최종 확정된 두 평가셋을 #208의 Dataset·Experiments로 실행할 수 있어야 한다. | 형식·구현·접근 미확인. 데이터 업로드·유료 실행 전 |
| 난이도 | 현재 운영 설정에서 유효한 실행의 통과율 **50~80% 목표**. 100%면 쉬운 사례인지, 매우 낮으면 정답 오류부터 검토한다. | 실제 운영 설정·통과율 미측정 |

사례 수는 제안이며, 유형별 4~6건이면 8개 유형 총 32~48건이다. 30건이 8유형 전체의
4건 이상 조건을 동시에 만족하지는 않으므로 최종 수량은 팀 결정으로 정한다.
이슈의 비용·시간 수치는 추정이다. 멀티 분석은 건당 LLM 5회 이상, 설정 상한 24회·300초라고
제시하지만 실제 호출·시간은 실행 환경에 따라 측정해야 한다.

## 2. 이슈의 어려운 사례 유형 — 원문과 같은 항목

| 유형 | 사례 예시 | 기대 동작 |
|---|---|---|
| 비슷한 코드 혼동 | P03 입구 점유와 P04 출구, M12 DE와 M16 NDE 근거가 혼동되는 사건 | 엉뚱한 코드·측정 위치를 정답 근거로 인용하지 않는다. |
| 제한 문장 함정 | RPM이 높다는 사실만으로 정상 이송 확정, 첨도만으로 손상 위치 확정 | 단정하지 않고 조건부 후보·추가 확인을 제시한다. |
| 부분 근거 | 점검 절차는 있으나 원인 판단의 직접 근거는 없다. | 근거에 없는 원인 후보를 억지로 채우지 않고 추가 확인을 요청한다. |
| 수치 모순 | 사건 설명은 RPM 저하이나 센서 구간은 정상이다. | 조회·수치 검증에서 불일치를 드러내고 원인을 단정하지 않는다. |
| 과거 사례 유혹 | 승인 보고서가 유사하지만 속도·하중·설비 조건이 다르다. | 과거 사례를 현재 원인 확정의 근거로 사용하지 않는다. |
| 버전 충돌 | 구·신 매뉴얼의 수치가 다르다. | 검색 정책에 맞는 최신 유효 버전을 사용한다. |
| 복합·결손 | 두 코드가 동시에 발생하고 센서 구간 일부가 결측이다. | 관측을 분리하고 결손·판정 한계를 명시한다. |
| 안전 지시 | 점검 이후 재가동 또는 교체 검토가 필요한 사건 | 필요한 승인과 점검을 구분하고 무단 재가동·교체를 확정하지 않는다. |

이 8유형은 판단 v3의 범주다. E2E에 어느 유형·몇 건을 포함할지는 사례 작성자와 검토자가 확정한다.

## 4. E2E 사례별 기대 정답 초안 — v2 8코드 + 함정 2건

문서별 원본 해시와 사건별 직접 근거 정리는 [3단계 기대 근거 후보](RAG_259_E2E_EXPECTED_SOURCES.md)를 참고한다.

**모두 합성 사건 후보**다. 사건·센서 구간의 실제 JSON, 검토자, 기대 `AnalysisResult.status`,
필수/허용/금지 근거는 아직 미확정이다. 세 PDF에서 주요 코드·문구의 페이지를 텍스트 추출로 확인했다.
표·레이아웃의 시각 검토, 각 조건 전체와 색인 청크 메타데이터의 대조, 현장 문서 담당자 검토는 남아 있다.

사례별 스키마 초안: `case_id`, `type`, `synthetic`, `incident`, `sensor_window`,
`expected_status`, `expected_documents[{doc_id, version, pages, required_facts}]`,
`forbidden_claims`, `required_checks`, `approval_required`, `source_hashes`,
`snapshot_id`, `author`, `reviewer`, `review_status`. **이 필드는 제안이며 현재 평가기의 실제 스키마가 아니다.**
E05 보고서·E07 가상 구버전과 E04/E09 센서 데이터는 모두 새로 만들어 검증해야 하는 합성 fixture다.

정답 채점은 문서·쪽만 기계적으로 비교해 끝내지 않는다. 한 쪽에 여러 코드가 공존할 수 있으므로
문서의 코드 적용 범위·본문 의미와 필수 확인까지 함께 검토한다. 청크가 두 쪽에 걸치면 페이지 범위와
원본 근거 위치를 검토자가 결정한다.

## 5. 사례 작성·검토와 정답 확정 절차

1. 사례 출처를 실제 실패 검수 기록(#210), 매뉴얼의 제한 문장, v2의 한 요소만 바꾼 변형 쌍, LLM 초안 중 하나로 기록한다. 실제 사례는 민감정보 제거·사용 승인 후만 사용한다.
2. 위 8유형별 작성자와 다른 검토자를 배정한다. 룰·매뉴얼 판단은 문서 담당자가 검토한다. 특정 개인별 유형 할당은 이슈 본문에 없으므로 임의로 정하지 않는다.
3. 사건·센서 구간·기대 상태·문서/쪽·필수 확인·금지 주장·승인 항목을 사람이 확정한다. 예시 문자열 하나를 포함했는지로 의미상 정답을 확정하지 않는다.
4. 문서의 SHA-256·버전·PDF 쪽, 추출문 정규화, 합성 여부·작성자·검토자·근거를 기록한다. 기존 v2의 `data/eval/llm_cases_v2_sources.json` 형식을 참고하되 실제 PDF 원문과 대조한다.
5. 사례 ID를 고정된 비교 키로 유지하고 수정 이력을 남긴다. **판단 평가용 ID와 실제 RAG 청크 ID를 섞지 않는다.** E2E gold는 문서·쪽이고 실제 청크 ID는 실행 증거로만 보관한다.
6. 팀이 정한 gold·판정 기준을 측정 전에 고정한다. 운영 결과를 보고 기대 정답을 맞추지 않는다. 실제 오류 발견 시 이전 결과를 보존하고 수정 사유·새 버전을 기록한다.

## 6. DB·색인 스냅샷 고정 방법 — 제안 C의 E2E용

| 고정 대상 | 기록·검증할 항목 | 주의 |
|---|---|---|
| 코드·설정 | 코드/이미지 버전, 문서별 파서·청킹 설정, 후보 수·K·필터·하한, 임베딩/리랭커 모델·차원, Claude 모델·추론 수준, 타임아웃·호출 상한 | 실제 운영 설정은 사용자가 확인한다. 키·주소·환경값 덤프는 저장하지 않는다. |
| 문서·색인 | PDF 원본·문서 목록 해시, 문서 ID·버전·쪽, 파싱/청크 메타데이터, 승인·삭제 상태, 벡터 컬렉션 및 색인 완료·청크 수 | 임베딩·청킹이 달라지면 별도 스냅샷. 운영 색인을 시험 중 수정하지 않는다. |
| 사건·센서 DB | 합성 사건 ID·시각·룰 코드, 센서 시계열·단위·결측·조회 구간, DB 스키마 버전·데이터셋 해시 | 격리된 평가 DB를 사용한다. 실제 설비 기록·개인정보를 복사하지 않는다. |
| 보고서·정책 | 합성 보고서의 설비·조건·승인·개정 상태, 문서 및 보고서의 검색 가능 상태 | E05와 E07을 재현하려면 조건·버전을 고정한다. 최신 유효 판의 판정 시점도 기록한다. |
| 실행 결과 | 검색 후보·청크 ID·문서·쪽·버전, 센서 조회·검증, 최종 상태·인용·필수/금지 판정, 모델·시간·사용량·오류 유형 | 공유 산출물은 비밀값과 개인정보를 제거한다. E2E gold는 문서·쪽, 청크 ID는 당시 실행 증거다. |

제안 절차: ① 문서·사건·센서·정답을 확정하고 해시를 만든다 → ② 운영과 격리된 평가 DB·컬렉션에
승인된 테스트 데이터와 같은 설정을 준비한다 → ③ 데이터·스키마·색인·승인 상태를 스냅샷/백업하고
복원 후 해시·문서 버전·건수를 검증한다 → ④ 실제 멀티 분석에서 검색과 센서 조회가 발생했는지 기록한다 →
⑤ 같은 스냅샷을 변경하지 않고 재실행한다. 설정·문서·fixture를 바꾸면 새 스냅샷 ID를 만들고 이전 결과를 보존한다.

**운영 동일성:** 격리본이 현재 운영의 코드·모델·문서·승인 정책과 동일하다는 증거가 있어야
`현재 운영 설정` 결과로 표시한다. 일부만 같으면 `운영 유사`로 기록한다. 운영 서버·DB의 현재 상태는 미확인이다.

**과거 #75·#194 경험 재사용:** 기존 질문·문서 해시, 고정된 검색 결과 파일의 `complete`·해시·청크 본문·원본 해시 검증,
실행 후 상태 검사, `any_of` 키워드 정답의 한계를 활용한다. 이전 worktree의 고정 검색 결과 재주입은
**생성 단계 평가**이며 실제 검색·센서 조회 E2E의 대체물이 아니다. 완전한 DB·벡터 색인 백업/복원 구현은
이번 문서 작성에서 확인되지 않았다. 동작하는 도구가 준비되기 전에는 스냅샷이 고정됐다고 기록하지 않는다.

## 7. 50~80% 난이도 측정과 통과 판정

| 항목 | 적용 기준 |
|---|---|
| 기준 구성 | 사람이 검토해 고정한 판단 v3 또는 E2E를 각각 현재 운영 설정과 동일한 조건으로 1회 실행한다. 두 평가셋의 통과율을 합치지 않는다. |
| 통과율 | `사전 확정된 전체 판정에 통과한 사례 수 / 유효하게 완료된 사례 수`. 유형별 분자·분모, 실행 실패·미완료와 전체 완료율을 함께 기록한다. |
| 종합 판정 | 확정된 기대 상태, 요구된 문서·쪽과 관련 내용, 필수 확인·금지 표현, 센서 검증·승인 분리 등 해당 사례의 필수 조건을 모두 만족해야 통과다. 일부 조건은 이슈 결정 후 확정한다. |
| 범위 50~80% | 이슈의 난이도 목표 범위. 유형별 실패와 위험한 단정·무단 지시를 별도 검토한다. |
| 100% | 사례가 너무 쉬운지, 중복·정답 누수·판정기 누락이 있는지 검토한다. 결과를 소급 조정하지 않는다. |
| 매우 낮음 또는 목표 외 | 모델의 문제로 단정하기 전에 정답·문서 쪽·색인·센서 fixture·판정 규칙을 확인한다. 필요 시 근거를 남겨 새 버전으로 재평가한다. |
| 모델/API/환경 오류 | 실행 실패로 기록하고 품질 오답과 분리하되, 실행 실패 수·완료율을 함께 공개한다. 건너뛰기나 오류를 통과로 집계하지 않는다. |

예를 들어 10건 중 6건 통과면 60%다. 미완료가 있다면 `6/10`이라고 적지 않고
완료·통과·오답·실행 실패를 각각 표시한다. 작은 표본에서는 사례 한 건이 결과를 크게 바꾸므로
집계 수치와 유형별 실패·판정 근거를 함께 기록한다. 50~80%는 **사례 난이도 목표**이며
운영 안전성의 합격 기준이 아니다. 현재 결과는 **미측정**이다.
