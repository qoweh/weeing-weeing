# 건수 전용 응답과 검토 근거 중복 제거 (v13)

사용자가 반영한 간결한 답변 지침 등 SYSTEM 전체 본문은 수정 전과 동일하게 유지했다. 새 동작은 도구 입력의 purpose와 서버 코드에서 처리한다. 공개 ChatResponse/출처 계약·DB 스키마·Detector·ML 모델은 바꾸지 않는다.

## 건수 전용 경로

`query_history`의 내부 입력 스키마에 `purpose=LIST|COUNT_ONLY`를 추가했다. 기본은 LIST이며 기존 입력과 호환된다. 질문 전체가 승인 정비 보고서 건수만 요구할 때 모델이 COUNT_ONLY를 선택한다. 목록·조치 설명·다른 자료도 필요한 복합 질문은 LIST로 처리한다.

COUNT_ONLY는 같은 응답의 도구가 하나이고 이전 조회/근거가 없을 때만 허용한다. 다른 도구와 섞이면 입력 오류를 반환해 일반 조회 경로로 수정하게 하며, 복합 답변을 첫 건수만으로 잘라 종료하지 않는다. 이 판단은 모델의 purpose 선택에 의존하며 모든 자연어 질문에 대해 자동 정확성을 보장하는 규칙 분류기는 아니다.

서버가 기존 조건 적용 규칙과 승인 보고서 필터를 거쳐 집계 출처를 만든다. 출처의 조건/코드/총수와 최신성을 검증하고 고정 템플릿으로 응답한다. 본문에는 총수(가상 자료가 포함되면 해당 건수), 실제 적용 기간/설비/코드, 한국 시간 실제 조치일 기준을 표시하며 보고서 목록이나 원인/조치는 포함하지 않는다. 0건도 조건이 명확한 유효 출처로 반환한다. 장애·출처 불일치·조회 중 변경은 정상0건으로 바꾸지 않고 실패 처리한다.

이 경로는 `submit_answer`를 생성하기 위한 추가 LLM 왕복 및 자유 답변의 LLM 근거 검토를 하지 않는다. 서버 코드가 만들고 검증한 ChatResponse로 runtime을 종료한다. 단독 COUNT_ONLY를 첫 응답에 요청하면 LLM1회로 끝나며, 일반 설명은 기존 작성/검토를 유지한다. runtime 종료 슬롯은 서버 핸들러만 설정하고, 입력 오류와 새 실행 때 초기화한다.

`DatabaseChatKnowledge.count_history()`는 보고서를 검색 hit/본문으로 가공하거나 모델에 보내지 않는다. 기존 저장소는 날짜 필터와 승인판 스냅샷 검증을 위해 여전히 보고서 객체를 읽는다. SQL COUNT만 실행하는 DB 최적화나 건수 캐시는 이번에 추가하지 않았다. LIST와 COUNT의 출처 식별자·집계 범위는 동일하다.

## 검토 근거 축소

최신 dev는 이미 인용 출처별 풀을 사용하고 있었으므로 기존 동작을 무조건 새 최적화라고 주장하지 않는다. 구형 로컬도 같은 형식으로 맞추고, 추가로 서로 다른 출처 ID의 본문이 정확히 같을 때 본문을 한 번만 보낸다. 각 ID의 출처 메타데이터와 각 답변 부분의 인용 연결은 유지하고 중복 항목은 text_ref로 본문을 공유한다. 검토 프롬프트에는 이 참조를 읽는 형식 설명만 필요한 경우에 덧붙인다.

인용하지 않은 자료는 답변 검토 입력에서 제외한다. 전문의 조건·예외·수치·앞뒤 문맥을 자르거나 별도 LLM으로 요약하지 않는다. 의미를 보존한다고 확신할 수 없는 구간 축소 대신 원문 전체를 유지하는 안전한 경로다. 본문이 다르면 합치지 않으며, 자유 답변은 동일한 근거 검토와 출처 최신성 검사를 계속 받는다.

payload의 evidence_stats에 중복 제거 전 참조 문자 수와 실제 전송 본문 문자 수를 기록한다. 문자 수 감소는 토큰/지연 감소를 보장하지 않으며 실제 비용·시간은 동일 조건에서 측정해야 한다.

## 로컬 확인

현재 실행 중인 챗봇은 종료 후 다시 시작한다. 기존 로컬 A/B 실행기와 질문 세트가 있는 경우 후보 버전을 v13으로 기록한다. A/B 모두 현재 서버 코드를 쓰고 프롬프트만 교체하므로 이 비교만으로 COUNT_ONLY 코드 도입 전후의 효과를 분리해 주장할 수 없다. 코드 도입 효과는 호출 기록의 purpose/도구/출처와 이전 실행을 별도로 대조해야 한다.

자동 검사는 가짜 클라이언트로 0/양수 집계,1회 종료, 일반/복합 경로, 조건 불일치·출처 변경·DB 장애, 조치일의 한국 시간 경계, 본문 미가공 및 원문/출처 보존을 확인한다. 자동 검사에서는 유료 LLM 호출을 하지 않는다. 배포 여부와 대상 SHA는 연결된 PR 및 GitHub Actions 기록에서 확인한다.

## 기존 측정과 남은 확인

`docs/evaluation/chat_roundtrips_20261105.json`의 통합 질문 4쌍은 작성/도구 턴 평균이 3.25→2.25회였다. 양쪽 모두 OK인 3쌍은 3→2회였다. 이는 v9의 여러 개선을 함께 비교한 과거 측정이며 v13의 효과나 단독 병렬 지침의 인과적 효과를 뜻하지 않는다.

사용자가 제공한 v12 측정의 수치만 `data/eval/chat_prompt_v12_latency_20261106.json`에 보존했다. RPM 질문은 빨라졌으나 통합/건수 질문은 빨라지지 않았다. 답변 본문·출처 ID·요청 ID는 포함하지 않는다. v13 실측 지연 및 사람의 답변 품질 판정은 별도로 필요하다.

독립 조회를 같은 LLM 응답에 요청하는 지침은 유지한다. 서버 도구 병렬 실행은 공유 메모리·출처 처리 순서를 고려해 검토만 하고 이번 변경에는 넣지 않았다. COUNT_ONLY 단일 도구 종료와 submit_answer의 순차 검증을 유지한다. 전체 지연 목표 및 스트리밍은 상위 이슈 #214의 미완료 과제로 남는다.
