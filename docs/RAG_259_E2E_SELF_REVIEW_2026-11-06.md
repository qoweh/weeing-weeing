# #259 E2E 사건 10건 Codex 자체 검토와 사람 검토 대기표

검토일: 2026-11-06. 대상은 [작성된 10건](RAG_259_E2E_CASES_V1_REVIEW.md)이다. PDF 원문과 [기대 근거 후보](RAG_259_E2E_EXPECTED_SOURCES.md), 현재 계약 코드 및 `origin/dev`의 멀티 분석 검색 경로를 **읽기 전용**으로 대조했다. 실제 검색·DB·API 평가 결과는 아니다. 작성자가 수행한 자체 검토이므로 #259에서 제안한 **다른 사람의 교차 검토를 대체하지 않는다**.

## 실행 전에 확인할 공통 조건

1. `TelemetryRecord`는 1초 집계 행이다. 센서 조회 도구는 시작·끝·수집 완료 시각과 반환 표본 간격을 별도로 기록한다. 특히 E09의 빠진 행을 `rpm=0`이나 정상값으로 치환하지 않는다. 현재 체크아웃과 `origin/dev`의 센서 품질 판정 코드는 다를 수 있으므로 평가할 커밋의 결과를 사용한다.
2. 현재 작업 폴더의 `AnalysisResult.status`는 `OK`, `INSUFFICIENT_EVIDENCE`, `FAILED`지만 `origin/dev`의 멀티 분석 계약에는 `VERIFICATION_FAILED`가 추가됐다. 룰 단계의 `Unknown`을 API 결과 상태에 그대로 쓰지 않는다. E04·E09처럼 자료가 상충하거나 결손된 경우의 기대 상태는 **평가할 코드 버전**의 계약과 사람이 확정한다.
3. `origin/dev`의 멀티 분석 보고서 검색 경로는 같은 설비·공정·코드, 승인 상태와 정비 입력을 확인한다. E05는 이 조건을 만족하는 **합성** 보고서를 격리 DB에 만들어야 검색 유혹을 검증할 수 있다.
4. E07의 가상 구버전과 E01/E02의 다른 코드 문구가 실제 검색 후보에 나타나는지 확인한다. 필터가 모두 제거하면 어려운 판단을 검증한 결과로 해석하지 않는다.
5. 기대 문서·쪽은 실제 검색된 청크의 문서 ID·버전·PDF 쪽·본문을 대조해 확정한다. 같은 PDF 쪽에 여러 코드가 있어 **해당 문장의 적용 범위**도 검토한다.

사람 검토자는 각 사례에 대해 `검토자`, `검토일`, `승인/수정 필요`, `근거 문서·쪽`, `기대 상태`, `필수·대체 허용 근거`, `금지 표현`, `필수 확인`, `수정 사유와 새 버전`을 기록한다. 현재 모든 항목은 **교차 검토 대기**다. 실제 E2E에 넣을 gold가 확정되거나 50~80% 난이도를 측정한 것으로 표시하지 않는다.
