# #259 E2E 후보의 원문·중복 검토

작성일: 2026-11-06. 대상은 [E01~E10 기대 근거 후보](RAG_259_E2E_EXPECTED_SOURCES.md)다. 세 PDF의 해당 쪽에서 추출한 본문, [v2 판단 사례](../data/eval/llm_cases_v2.toml), 이전 worktree의 `data/eval/rag_queries_100_candidate_v1.toml`을 대조했다. 원본 SHA-256은 기대 근거 후보 문서에 기록했다. 최초 검토에서 일부 쪽만 이미지 확인했으나 2026-11-06에 [관련 페이지 전체 시각 검토 및 청크 메타데이터 대조](RAG_259_STEP4_INDEX_METADATA_REVIEW.md)를 추가했다.

v2는 같은 사건마다 `correct`, `mixed`, `unrelated`, `none` 등으로 고정 근거를 바꾼 판단 평가다. 위 표의 `*-correct` 등은 관련 사례를 찾기 위한 참조이며, 기존 v2의 평가 전용 근거 ID를 실제 검색 청크 ID로 쓰지 않는다. 100문항은 이전 worktree에 있는 **검색 질문 후보**이고 채택 여부와 독립 평가 여부는 별도다. 코드나 주제가 같다고 E2E 전체가 중복이라고 확정할 수 없으며, 반대로 차별 조건이 구현되기 전에는 새 독립 평가 사례라고 볼 수도 없다.

## 페이지와 색인 점검

- 현재 코드의 [PDF 파서](../src/weeing_weeing/rag/pdf_parser.py)는 페이지를 1부터 세어 `page` 메타데이터에 넣는다. [구조화 청킹](../src/weeing_weeing/rag/structured_chunker.py)은 페이지별로 처리하고 메타데이터를 복사하며, [인덱서](../src/weeing_weeing/rag/indexer.py)는 해당 `page`를 청크에 넣는다. 이는 **코드 검토 결과**다.
- 보존된 2026-10-30 색인기 감사 캡처에서 청크 ID·문서 버전·페이지·본문을 대조했다([상세 기록](RAG_259_STEP4_INDEX_METADATA_REVIEW.md)). 이 캡처는 메모리 저장소에 전달된 파서·청커 출력으로, 현재 운영/평가 벡터 컬렉션의 지속 스냅샷은 아니다. 실제 사용 컬렉션 ID·설정·백업 상태는 확인되지 않았다.
- 3단계의 문서·페이지는 직접 근거 후보로 유지한다. 사례별 검색 정답을 `필수`, `대체 허용`, `보조` 중 어떻게 분류할지는 실제 사건과 검색 정책이 정해진 뒤 결정한다. 같은 페이지에 여러 코드가 있어 페이지 일치와 본문 적용 가능성을 함께 확인해야 한다.

## 남은 확인

1. 평가 담당자가 실제 사용할 색인의 스냅샷 ID를 만들면 청크 메타데이터를 해당 백업에서 재대조한다. 색인 고정·복원 방법 자체는 5번에서 이미 문서화했다.
2. E05 승인 보고서와 E07 가상 구버전 등 추가 함정 fixture는 평가 담당자가 실행 입력으로 만들 때 새 ID·본문·승인/버전 메타데이터를 대조한다. 이를 현행 색인에 이미 있다고 가정하지 않는다.

4번의 본인 담당 대조는 위의 원문·시각·청크 메타데이터·승인 입력 기록으로 완료했다. 현재 운영/평가 컬렉션의 지속 스냅샷은 없어 운영 상태 확인이나 백업·복원 완료로 해석하지 않는다. 운영 설정의 50~80% 통과율은 아직 측정하지 않았다.
