이번 문서 정리에서 DB·모델·API를 새로 실행한 결과가 아니다.

이 값은 초기 평가 후보와 준비 확인 기록이다. 현재 운영 설정과 동일하다는 의미가
아니며 실행 프로세스의 실제 공개 설정을 결과와 함께 다시 기록한다.
검색 평가의 `-k 5`는 멀티 분석의 K를 설정하는 환경변수가 아니다.
Qdrant 컬렉션은 실제 공급자·모델·차원·dense/sparse 설정과 맞게 생성해야 한다.
주소·인증값·전체 환경 덤프는 문서와 산출물에 넣지 않는다.

## 재사용 경계와 fixture 계약

- 고정 근거의 v2·고정 검색 결과 재주입은 판단/생성 평가다. 실제 검색·센서 조회가
  발생하는 멀티 E2E와 분리한다. 싱글 분석 CLI 성공을 멀티 E2E로 집계하지 않는다.
- 사례·정답은 [승인 사례](RAG_E2E_CASES.md), 문서·쪽·본문과 해시는
  [근거 대조](RAG_E2E_SOURCES.md)를 기준으로 고정한다.
- 합성 기본값과 사례별 5분 간격 시각은 사용자 승인 기록을 따른다.
  동일 설비·공정·시각의 telemetry 유일 제약과 사건 ID 갱신 동작을 고려해 적재 전
  충돌을 검사하고 기존 사건·센서 데이터를 덮어쓰지 않는다.
- E09의 `t=9초`는 센서 행 전체 부재다. RPM을 0·정상·직전 값으로 채우지 않는다.
- E08의 NDE 결손은 현재 필수 NDE RMS·첨도 필드와 충돌한다. 가짜 정상값으로
  채우면 승인 사례의 의미가 달라지므로 표현을 확정할 때까지 보류한다.
- E05의 같은 설비·공정·코드 합성 승인 보고서와 E07의 평가 전용 구버전은 별도
  검색 자료다. 사건·센서 9건 준비만으로 두 함정의 실행 준비를 완료 처리하지 않는다.

## 하나의 스냅샷으로 묶을 항목

`snapshot_id`는 평가 기록용 불변 식별자다. 현재 실행기에 자동 구현된 필드라는
뜻은 아니다. 코드·문서·fixture·gold·설정 중 하나가 바뀌면 새 ID를 부여한다.

| 대상 | 보존할 내용 | 복원 후 비교 |
|---|---|---|
| 코드·공개 설정 | 커밋·소스 변경, 파서/청킹·모델/차원·후보/K/필터/하한·시간/호출 상한 | 실행 코드·설정 동일성 |
| 문서·정답 | PDF·목록·사례·gold SHA256, 문서 ID/버전/쪽, 검토 버전 | 원본·정답 해시 |
| 색인 | 전체/문서별 건수, 청크 ID·버전·쪽·본문 해시·검색 가능 상태, 컬렉션 설정·백업 ID/해시 | 개수·ID·메타데이터·본문 해시 |
| 사건·센서 DB | 스키마, 합성 사건 ID/코드/시각, 표본·단위·결측, 보고서 승인/개정, 백업 ID/해시 | 사건·표본·기간·결측·승인 상태 |

검색 후보 결과 파일과 PDF 해시만으로 DB·벡터 저장소의 지속 백업을 대체하지 않는다.
`verify_rag_e2e.py`는 임시 저장소/컬렉션을 정리하므로 재사용 가능한 영속 스냅샷을
만드는 도구로 취급하지 않는다.

## 생성·복원·평가 순서

1. 실행 커밋·승인 정답·격리 원본/복원 대상과 공개 설정을 고정한다.
2. 합성 사건·센서·보고서·버전 자료를 검증해 적재하고 색인 완료를 확인한다.
3. 평가 환경의 쓰기를 멈춘 상태에서 DB와 색인을 각각 백업한다. 백업 파일 해시·
   도구 버전·문서/청크/표본 목록을 함께 보존한다.
4. 원본과 다른 격리 대상에 복원하고 위 표의 건수·ID·본문 해시·결측·승인 상태를
   비교한다. 불일치하면 평가 전에 원인을 확인한다.
5. 동일 복원본에서 멀티 분석을 실행하고 실제 검색·센서 조회·후보·최종 인용·상태·
   필수/금지 판정·모델·호출/시간/사용량을 사례별로 기록한다.
6. 실행 전후 지문을 비교하고, 결과·스냅샷 ID·복원 증거를 함께 인계한다.
   정답 변경이 필요하면 이전 실행을 보존하고 사람 재검토 후 새 버전으로 평가한다.

백업·복원 명령은 격리 대상에 맞춰 평가 담당자가 수행한다. 실제 인증·유료 API는
사용자가 자기 터미널에서 실행하며 AI의 자동 검증에는 가짜 클라이언트만 사용한다.
IDE 열린 파일·선택 코드가 자동 문맥에 포함될 수 있으므로 실제 키는 편집기·예시
파일·채팅에 입력하지 않는다. 실제 비밀 파일이나 SDK 인증 프로필을 열지 않는다.

## 결과 집계와 인계

통과율은 사전 확정한 모든 판정에 통과한 사례 수를 유효 완료 사례 수로 나눈다.
예정 수·완료 수·품질 오답·실행 오류·보류를 함께 표시해 실행 실패를 분모에서
숨기지 않는다. 유형별 결과도 별도로 남긴다.
**50~80%는 사례 난이도 목표이며 측정 결과나 운영 안전성 합격 기준이 아니다.**
100% 또는 매우 낮은 값이면 정답·누수·fixture·판정기·난이도를 검토하되 결과에 맞춰
gold를 소급 변경하지 않는다. 판단 v3와 E2E의 통과율은 합치지 않는다.

인계 묶음은 승인 사례·출처 지문·스냅샷/복원 대조·실제 검색/센서 기록·최종 응답·
판정 사유다. Langfuse Dataset/Experiment 연결은 팀 평가 작업으로 추가하며,
현재 문서 작성이나 로컬 준비만으로 업로드·배포 완료를 주장하지 않는다.
보완 과제는 [문서 안내](README.md)에서 관리한다.
