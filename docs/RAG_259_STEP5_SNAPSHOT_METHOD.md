# #259 멀티 분석 E2E 색인·DB 스냅샷 고정 방법

작성일: 2026-11-06. [#259 사례 후보](RAG_E2E_DIFFICULT_CASES_259_DRAFT.md)의 E2E를 같은 자료로 반복 실행하기 위한 **방법 정의**다. 실제 평가 색인·DB 백업이나 복원은 아직 수행되지 않았다. 이 문서의 `snapshot_id`는 평가 기록용 제안 필드이며 현재 실행기의 실제 필드가 아니다.

## 현재 저장소에서 확인한 경계

- [검색 E2E 실행기](../scripts/verify_rag_e2e.py)는 평가 문서 3종을 임시 저장소에 색인한다. `qdrant-server`도 실행 후 임시 컬렉션을 삭제한다. 결과 보고서만으로 재사용 가능한 색인 스냅샷이 남지 않는다.
- [PDF 파서](../src/weeing_weeing/rag/pdf_parser.py)는 PDF 쪽을 1부터 세어 메타데이터에 기록한다. [청킹](../src/weeing_weeing/rag/structured_chunker.py)은 쪽별 내용을 분할하고, [인덱서](../src/weeing_weeing/rag/indexer.py)는 문서 ID·버전·쪽과 본문으로 청크를 만든다. 실제 사용 색인의 청크 본문·메타데이터는 별도 확인이 필요하다.
- `CertUtil -hashfile` 성공은 해시 **계산 성공**을 뜻한다. [3단계 문서의 원본 해시](RAG_259_E2E_EXPECTED_SOURCES.md)와 출력값이 같은지 대조해야 원본 일치를 확인할 수 있다. PDF 해시만으로 청킹·임베딩·벡터 컬렉션·DB 내용의 고정은 증명되지 않는다.

## 고정 단위

동일 평가 실행에 다음 4가지를 하나의 `snapshot_id` 아래 묶는다. 하나라도 바뀌면 새 ID를 만들고 이전 결과를 보존한다.

| 대상 | 보존·기록할 항목 | 재실행 전 확인 |
|---|---|---|
| 코드·설정 | Git 커밋, 파서·청킹 설정, 검색 필터, 후보 수·최종 K·하한, 임베딩 공급자·모델·차원, 리랭커 모델, 분석 모델·추론 수준·호출 상한 | 공개 설정값만 기록한다. 연결 주소·인증값·환경 전체는 기록하지 않는다. |
| 문서·정답 | PDF 3종과 `rag_documents_v1.toml`의 SHA-256, 문서 ID·버전·PDF 쪽, 사례 파일·정답 파일의 해시, 사람의 검토 버전 | [기대 문서·쪽 후보](RAG_259_E2E_EXPECTED_SOURCES.md)를 정답 확정값으로 자동 전환하지 않는다. |
| 색인 | 격리된 평가 컬렉션 이름/식별자, 임베딩 차원·컬렉션 메타데이터, 완료 시점의 전체·문서별 청크 수, 각 청크의 문서 ID·버전·쪽·본문 해시와 검색 가능 상태, 백업 식별자 | 백업에서 별도 평가 컬렉션으로 복원해 개수와 메타데이터를 비교한다. 실제 운영 컬렉션은 대상으로 삼지 않는다. |
| 사건·센서 DB | 격리 평가 DB의 스키마 버전, 합성 사건·설비 ID, 코드·시각, 센서 구간·단위·결측, 승인 보고서의 상태·개정, 백업 식별자와 평가 데이터 해시 | 복원 후 사건 수·표본 수·ID·기간·결측·승인 상태를 대조한다. 실제 설비 기록은 합성 fixture에 복사하지 않는다. |

`snapshot_id`는 예를 들어 날짜·Git 커밋 접두부·문서 목록 해시 접두부를 포함한 **불변 식별자**로 정한다. 충돌 방지를 위해 팀 평가 담당자가 할당한다. 파일명이나 컬렉션명만 같다는 이유로 동일 스냅샷으로 간주하지 않는다.

## 생성·복원·검증 순서

1. 팀에서 사례와 gold의 사람 검토를 끝내고, 격리 평가 DB·컬렉션과 운영 설정에 대응하는 공개 설정값을 정한다. E05의 합성 승인 보고서와 E07의 가상 구버전은 실제 fixture가 생긴 경우에만 목록에 포함한다.
2. 원본·사례 파일의 해시와 Git 커밋을 기록한다. 사용자가 CMD에서 실행한 `certutil -hashfile` 결과의 **해시 문자열**을 [3단계 기록](RAG_259_E2E_EXPECTED_SOURCES.md)의 PDF 해시와 대조한다. `CertUtil` 성공 메시지만으로 값 일치를 주장하지 않는다.
3. 평가 데이터만 적재한 뒤 색인 완료를 확인하고 문서별 청크 수·메타데이터·본문 해시를 내보낸다. 색인과 격리 DB를 각각 해당 저장소의 백업 기능으로 보존하며 백업 파일 자체의 해시와 도구 버전을 기록한다. 백업 완료 전 인덱싱·문서 개정·보고서 승인 변경이 동시에 일어나지 않도록 평가 환경의 쓰기를 멈춘다.
4. **원본과 다른 격리 대상**으로 복원한다. 컬렉션 메타데이터, 전체·문서별 청크 수, 문서 ID·버전·쪽·본문 해시를 원본 기록과 비교한다. DB 스키마·사건 수·센서 표본·결측·보고서 승인 상태도 비교한다. 하나라도 다르면 실행을 중지하고 새 백업을 만든다.
5. 복원된 동일 자료에서 검색을 반복해 사례별 후보 청크 ID, 문서 ID·버전·쪽·본문 해시, 순위·점수와 적용 필터를 남긴다. **검색 결과 고정 기록**은 결과 감사용이며 색인 백업을 대신하지 않는다. gold는 청크 ID가 아닌 문서·쪽과 해당 본문의 적용 조건으로 판정한다.
6. 평가 실행 뒤 재확인한 문서·DB·컬렉션 지문이 시작 전과 같은지 대조한다. 설정·fixture·gold가 바뀌면 새 `snapshot_id`로 실행하고 이전 결과와 변경 이유를 남긴다.

## CMD에서 바로 수집할 수 있는 비밀 없는 값

아래는 **원본 식별용**이다. 현재 작업 폴더에서 실행하고 결과 해시·커밋 ID만 기록한다. `.env`, API 키, DB 접속 정보, 환경변수 전체를 출력하거나 공유하지 않는다.

```cmd
cd /d C:\weeing-weeing
git rev-parse HEAD
certutil -hashfile data\eval\rag_documents_v1.toml SHA256
certutil -hashfile data\manuals\BTT-MANUAL_v2.0.pdf SHA256
certutil -hashfile data\rulebase\BTT-RULE_v2.0.pdf SHA256
certutil -hashfile data\regulations\BTT-SOP-001.pdf SHA256
```

이후 **실제 백업·복원 명령**은 평가 DB와 벡터 저장소의 위치·제품·접근 권한·격리 대상이 팀에서 확정된 뒤 작성한다. 현재 저장소에는 #259용 영속 색인·DB 스냅샷 생성/복원 명령이 없다. `verify_rag_e2e.py`의 임시 컬렉션을 백업 대상으로 착각하지 않는다. 백업·복원은 평가 담당자가 사용자 CMD에서 수행하고, Codex는 공개된 식별자·해시·건수·검증 결과를 대조할 수 있다.
