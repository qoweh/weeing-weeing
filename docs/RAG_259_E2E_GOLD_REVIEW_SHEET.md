# #259 E2E 정답 v1 — 사람 검토 완료

작성일: 2026-11-06. [합성 사건 10건](RAG_259_E2E_CASES_V1_REVIEW.md)의 사건 입력과 [PDF 원문 대조](RAG_259_STEP4_SOURCE_DUPLICATE_REVIEW.md)를 근거로 작성한 **정답 v1**이다. 작성자(Codex)와 다른 검토자(사용자)가 10건의 **기대 상태, 직접 근거 문서·PDF 쪽, 반드시 확인할 내용, 금지할 단정**을 전체 승인했다. 실제 DB·색인 fixture 및 청크와의 대조는 별도 후속 작업이다. `BTT-RULE`과 `BTT-MANUAL`은 모두 v2.0, `BTT-SOP-001`은 v1.1이다. 여기서 쪽은 PDF 첫 쪽을 1로 센 번호다.

상태는 평가 대상인 `origin/dev`의 멀티 분석 계약을 기준으로 확정했다. `OK`는 검색 근거가 있고 안전한 원인 **후보**·점검을 제시할 수 있다는 뜻이며 원인 확정이나 조치 승인과 다르다. `INSUFFICIENT_EVIDENCE`는 관련 문서가 있어도 사건의 핵심 관측을 신뢰할 수 없어 근거 있는 후보를 만들 수 없다는 기준이다. `VERIFICATION_FAILED`는 검증 단계에서 수정 요구가 반복된 **실행 결과**이므로 사례 작성 단계에서 기대 정답으로 예약하지 않는다.

이 표의 문서·쪽은 **사람이 승인한 평가 정답 범위**다. 실제 청크가 해당 쪽의 코드를 포함하는지와 인용 내용의 충분성은 fixture 생성 후 확인한다. E04는 사건 증거와 센서 DB가 충돌하므로 `INSUFFICIENT_EVIDENCE`를 정답으로 승인했다. 평가기가 다른 상태를 내면 먼저 입력·검증 정책을 확인한다. E09는 P01만 성립하는 부분 판정으로 승인했다.

## 검토 기록

사용자가 2026-11-06에 **E01~E10 전체 승인**을 답했다. 검토 요청에는 E04의 상태 선택, E07의 가상 구버전 정책, E09의 부분 성립 처리, E10의 승인 항목을 명시했다. 수정 요청은 없었다. 추후 정답을 고치면 이 버전과 결과를 보존하고 변경 사유·새 해시·재검토를 기록한다.
