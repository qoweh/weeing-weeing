# #259 멀티 분석 E2E 기대 근거 후보

작성일: 2026-11-06. [사례 초안](RAG_E2E_DIFFICULT_CASES_259_DRAFT.md)의 E01~E10에 대해 저장소 PDF의 텍스트를 대조한 **3단계 산출물**이다. 실제 사건과 센서 입력, 사례별 필수 정답, 기대 상태, 작성자·검토자는 확정되지 않았다. 아래는 정답 확정 전 검토 후보이며 사례 유형 배정과 독립적인 공통 준비다.

쪽은 PDF 파일의 첫 페이지를 1로 센 번호다. 표의 문서·쪽은 해당 내용을 확인할 수 있는 후보이며, 나열된 모든 쪽이 반드시 검색되어야 한다는 채점 조건은 아니다. 실제 필수·대체 허용 근거는 사건 입력과 평가 계약을 정한 뒤 사람이 결정한다. 같은 쪽에 다른 코드가 함께 있으므로 문서·쪽 일치만으로 코드와 내용의 정확성을 판단하지 않는다.

## 4단계로 넘길 확인 사항

1. 실제 사건·센서 구간·검색 대상과 각 사례의 필수 근거 및 허용 가능한 대체 문서·쪽을 작성자와 검토자가 확정한다. 검색 청크가 여러 쪽에 걸치는 경우 페이지 범위 비교 규칙을 정한다.
2. PDF 표와 각 조건을 시각적으로 확인하고 색인된 청크의 문서 ID·버전·페이지 메타데이터가 원문과 일치하는지 확인한다. 텍스트 추출과 문서 목록 대조만으로 정답 검토를 완료 처리하지 않는다.
3. 기존 v2 사례와 100문항 후보의 내용·출처를 대조해 재사용과 중복 여부를 기록한다. 기존 검색 평가 질문은 사건·센서 조회를 포함한 E2E 사례와 구분한다.
4. E05 합성 보고서, E07 가상 구버전, E04/E09 센서 결손·모순 fixture의 존재와 검색 정책을 확인한다. 확인되지 않은 자료의 ID나 해시는 만들지 않는다.
5. 도메인 담당자를 포함한 다른 검토자가 정답을 확인한다. 확정 전에는 측정 결과에 맞춰 gold를 조정하지 않는다. 운영 설정 기준 통과율 50~80%는 목표이며 이번 작업에서 실행하거나 측정하지 않았다.

색인·DB 스냅샷을 실제로 고정하는 구체적 방법과 검증은 5단계에서 별도로 정리한다.
