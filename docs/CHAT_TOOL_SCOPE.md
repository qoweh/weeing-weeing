# 조회 범위와 종료 기준 v12

시스템 프롬프트는 도구의 조회 대상·입력·반환 범위로 확인 가능한 요청만 조회하도록 한다. 전체가 지원 범위 밖이면 무조회 OUT_OF_SCOPE, 일부만 지원되면 그 부분만 조회하고 한계를 구분한다. 지원 범위 안의 일치 결과0건과 기능상 지원 불가를 구분한다.

NO_CANDIDATES의 DB0건 범위는 유지한다. NO_MATCHES/NO_RESULTS를 검색 장애로 부르거나 무조건 재검색하지 않는다. 필요한 근거가 부족하고 지정 조건을 유지한 검색어 개선으로 추가 근거를 얻을 수 있을 때만 재조회한다. 근거 확보 또는 확인 가능한 한계가 명확하면 종료한다.

도구 description에는 다음 실제 계약을 전달한다.

- search_knowledge: 등록 승인 문서/최신 승인 정비이력의 관련 본문, 검색 수와 전체 수 구분, 기록되지 않은 외부 현재 상태는 직접 조회하지 않음.
- query_history: 보고서별 최신 승인판 중 정비 내용이 있는 대상, 한국 시간 실제 조치일 기준(양 끝 포함), 등록일/미승인판 포함 집계 아님, total과limit 구분.
- query_incidents: 기록된 사건 사실, 상태별 대상·시간 기준과 최신 회복1건 조건, source/evidence 사용, 직접 측정/원인 확정/제어 아님.
- browse_faq/get_faq_answer: 등록 목록과 실제 고정 답변 조회 역할 구분.

중복된 사건 지침을 압축해 시스템 본문은2451자에서2410자로 줄었다. 도구 설명과 입력 스키마도 LLM에 전달되므로 전체 입력 토큰이 줄었다는 의미는 아니다. 더 정확한 범위 판단으로 조회·재작성 감소가 있는지는 유료 비교 실험으로 별도 확인해야 한다.

버전은 chat-tools-v12다. 기존10요청 A/B 실험이 있는 로컬 폴더는 v10 기준 프롬프트를 그대로 보존하고 현재 후보 이름을v12로 갱신했다. 같은 실행 코드에서 프롬프트만 비교한다.

자동 검사는 실제 LLM 요청에 description/input_schema가 전달되는지, 모델이 OUT_OF_SCOPE로 제출한 경우 조회/추가검토 없이1회로 종료 가능한지를 가짜 클라이언트로 확인한다. 모델이 새 지침을 실제로 준수한다는 품질 검증은 아니다. 조회 처리·DB/Detector/PLC 동작은 변경하지 않았다.

검증: 최신 dev 기반 전체 검사1874 passed, 7 skipped(기존 경고3개), 원래 로컬 챗봇/10요청 실행기 집중검사66개 통과. 유료LLM·AWS 배포는 미실행이다. 10요청 실행기는 시스템/검토 프롬프트4개만 교체하므로 도구 설명은 양쪽 모두 현재v12를 사용한다. 과거v10의 도구 설명까지 포함한 전체 배포본 비교는 아니다.
