## 결론

요청 설정 `claude-sonnet-5-5 / medium`을 사용한다. 기존 4사례를 3회 반복한 12건과
확대 32사례에서 형식·기대 상태·정답 근거 ID 대조가 모두 통과했다. 실제 P03 사건에서도
검색 관련도 전달·센서 조회·수치 검증이 동작했다.

초기 실측 당시 Opus 비교는 미완료였다. 초기 두 설정에서 응답 결과를 얻지 못했으며 추가 1건은 HTTP 429였다.
이후 팀이 비용 제약으로 Opus를 사용하지 않기로 합의해, Opus 비교를 #106 완료 조건에서 제외했다(D-30).
과거 실패를 추론 품질이나 속도가 낮다는 근거로 사용하지 않는다. 운영 모델·effort 및
RAG 하한은 변경하지 않았다. 초기 잠정 판단(D-29)은 이 기록과 함께 보존한다.

초기 Opus 오류는 첫 보고서에 상태 코드를 남기지 못해 24건 각각의 원인을 확정할 수 없다.
승인받은 추가 P03 1건에서 HTTP 429를 확인했다. 그 뒤 Opus를 추가 호출하지 않았다.
이후 비교 도구는 HTTP 오류 첫 건에서 중단하고 코드를 기록한다. 사용량 미수신은 무료 청구를 뜻하지 않는다.
Sonnet 응답에서 보고된 캐시 토큰은 0이었다. 토큰은 단가를 적용한 확정 비용이 아니다.

조건을 적용했다. 정답 있는 16건은 OK, 나머지 16건은 INSUFFICIENT_EVIDENCE였다.
한 번의 확대 실행이며 독립 검증셋·전문가 검토를 마친 일반 성능 수치는 아니다.

## 실제 검색·센서 도구 1사건

어제 저장한 P03 Error 스냅샷과 당시 DB 센서 구간을 사용했다. 8000번 서버는 사용자가 중지했고,
꺼져 있던 Docker 엔진·기존 PostgreSQL을 기동했다. 새 데이터베이스나 센서 입력을 만들지 않았다.
독립 분석 스크립트이므로 이번 결과를 분석 작업 DB에 새로 저장하지 않았다.

- 결과 OK. 검색 1회 → 센서 조회 1회 → 제출 1회, 모든 도구 성공.
- LLM 호출 2회. Agent 전체 114.67초, LLM 호출 구간 합계 9.27초.
  나머지 시간은 검색 등 LLM 외 경로에 포함되지만 개별 원인은 분리 측정하지 않았다.
- 관련도 후보 `0.02`를 자식 프로세스에만 적용했다. `.env`와 운영 기본값은 변경하지 않았다.
- 검색된 근거 5개, 인용 근거 2개. 반환 관련도는 약 0.148~0.962로 기준 이상이며 인용 ID 대조 통과.
  실제 제외 개수는 수집하지 않았다. 전부 제외되는 경로는 가짜 검색·센서 결합 테스트로 검증했다.
- 센서 조회 1회, 검증한 통계 2개: 입구 신호 마지막 True, 평균 RPM 1015.0.
  요청 시작 표본 부족과 최대 1.507초의 관측 간격 한계를 결과에 보존했다.
- 입력/출력 토큰 13,397 / 1,177. 종료 시 기존 Qdrant 소멸자 정리 경고
  `sys.meta_path is None`가 있었지만 분석 OK·지표 파일 저장·프로세스 종료 코드 0을 확인했다.

  승인 항목으로 구분했다. 다만 자유 서술의 모든 수치·조치 의미를 기계적으로 검증한 것은 아니다.
