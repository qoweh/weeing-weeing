# 웹 사건 코드 표시명

화면에서는 현장 용어를 앞에 표시하고 원래 코드 식별자를 작은 보조 글씨로 병기한다.
예: **모터 속도 저하** `(BTT2-M02)`. 판정 등급·회복 조건·코드값은 바꾸지 않는다.

## 공통 구현

- 표시명·기존 명칭 검색어·도움말: `frontend/src/components/ui/incidentCodes.ts`
- 화면 컴포넌트: `frontend/src/components/ui/IncidentCodeLabel.tsx`
- 반응형 줄바꿈·작은 코드·인쇄 스타일: `frontend/src/components/ui/IncidentCodeLabel.css`
- 적용: 상단 주의/경고, 사건 목록·상세·삭제 확인, 예측 후보, 정비 이력, 보고서 및 챗봇 보고서 출처.
- 센서 그래프 제목은 측정 항목이다. 정상 측정 중에도 오류처럼 보이지 않도록 그대로 유지한다.

31개 등록 코드의 원본 정의는 `src/weeing_weeing/contracts/codes.py`다.
프론트 표시명은 사용자와 검토한 별도 표현이며, 신규 코드나 공식 명칭 변경 시 대응 검사로 누락을 확인한다.
미등록 코드는 `미등록 코드 (원본 코드)`로 표시하고 숨기지 않는다.

## 표시 원칙

- 감지 사건: `모터 속도 저하 (BTT2-M02)`.
- ML 예측: `모터 속도 저하 가능성 (BTT2-M02)`와 기존 확률을 함께 표시한다.
- 한 사건에 코드가 여러 개면 각각의 표시명과 코드를 나란히 또는 여러 줄로 표시한다.
- 검색은 새 표시명, 기존 공식 명칭, 원본 코드와 띄어쓰기 차이를 지원한다.
- 보고서는 AI 분석이 없어도 공통 표시명을 사용한다. 저장된 분석 본문·보고서 값은 변경하지 않는다.
- 과거 사건·보고서의 구조화된 코드도 같은 표시를 사용한다. 사건번호와 보고서번호는 그대로 유지한다.
- 모터 온도는 외함 센서 기준, 진동 수준은 RMS 기준임을 도움말에 표시한다. 첨도는 다른 물리량으로 바꾸지 않는다.
- 상·하한 이탈을 시간 변화율로 오해하지 않도록 `급증·급락`으로 표시하지 않는다.
- M04/M19의 표시명 등록은 해당 룰의 미평가 조건을 해제하지 않는다.

## 검증

`frontend`에서 `node --test tests/incident-code-labels.test.mjs`로 31개 코드 대응,
방향·측정 의미, 한글/코드/기존 명칭 검색, 예측 표현, 미등록 코드,
실제 컴포넌트·정비 이력 표 렌더링과 보고서의 AI 비의존성을 검사한다.
